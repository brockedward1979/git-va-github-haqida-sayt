1

Papka yaratish va Terminal Asoslari

Git bilan ishlashdan oldin operatsion tizim terminalida (Command Line / Bash) fayl va papkalar bilan ishlash asosiy buyruqlarini bilish kerak.

TO'G'RI BUYRUQ Papka yaratish & kirish 
mkdir mening-loyiham
cd mening-loyiham
pwd

mkdir: Yangi papka ochadi.
cd: Papkaga kiradi.
pwd: Hozirgi turgan papka manzilini ko'rsatadi.

TESKARI BUYRUQ Chiqish & O'chirish 
cd ..
rm -rf mening-loyiham

cd ..: Bir pog'ona yuqoridagi papkaga qaytadi.
rm -rf: Papkani va uning ichidagi barcha fayllarni qaytarib bo'lmas darajada o'chiradi.

Eslatma: rm -rf buyrug'ini ishlatishda juda ehtiyot bo me: u fayllarni korzinaga tashlamaydi, birdaniga butunlay yo'q qiladi!
2

Git Initsializatsiya va Sozlamalar

Papkada Git versiyalar boshqaruvini yoqish uchun uni Git repository (ombor)ga aylantiramiz.

INIT & CONFIG 
git init
git config --global user.name "Ismingiz"
git config --global user.email "email@example.com"

git init papka ichida yashirin .git papkasini yaratadi va barcha versiyalarni kuzatishni boshlaydi.

DE-INIT (TESKARI) 
rm -rf .git

Agar loyihani Git nazoratidan chiqarmoqchi bo'lsangiz, shunchaki .git papkasini o'chirib tashlaysiz. Fayllaringiz o'chmaydi, faqat tarixi o'chadi.

3

Staging Area va Commit Jarayoni

Git-da o'zgarishlar uchta holatda bo'ladi: Working Directory (ishchi hudud) → Staging Area (tayyorlov hududi) → Repository (saqlangan commitlar).

BUYRUQLAR KETMA-KETLIGI 
# 1. Holatni tekshirish
git status

# 2. Faylni staging area-ga qo'shish
git add index.html
# Yoki barcha fayllarni qo'shish: git add .

# 3. O'zgarishlarni snapshot (commit) qilib saqlash
git commit -m "Initial commit: loyiha yaratildi"

# 4. Commitlar tarixini ko'rish
git log --oneline
4

Bekor Qilish va Orqaga Qaytish (Undo / Reverse Matrix)

Git-ning eng kuchli tomoni — istalgan xatoni bekor qilish imkoniyatidir. Har bir to'g'ri buyruq uchun unga mos keluvchi teskari buyruq mavjud.

1. Staging hududidan faylni chiqarish (Unstage) Staged → Unstaged
Qilingan ish:
git add script.js
Fayl commitga tayyor qilib qo'yildi.
Teskari buyruq (Bekor qilish):
git restore --staged script.js
Fayl stagingdan chiqariladi, kodingiz o'chmaydi.
2. Fayldagi yozilgan kodingizni bekor qilish (Discard changes) Modified → Clean
Qilingan ish:
# Faylga noto'g'ri kod yozib qo'ydingiz
Teskari buyruq:
git restore style.css
Fayldagi oxirgi commitdan keyingi barcha o'zgarishlar o'chib, ko'rsatilgan holatga qaytadi.
3. Oxirgi Commit-ni bekor qilish (Soft / Hard Reset) Commit → Undo
Qilingan ish:
git commit -m "Xatoli commit"
Teskari buyruq (Yumshoq / Qattiq):
git reset --soft HEAD~1
--soft: Commit yo'qoladi, lekin kodingiz staging-da qoladi.
git reset --hard HEAD~1
--hard: Commit ham, undagi kodlar ham butunlay o'chib ketadi!
4. Serverga push qilingan commitni xavfsiz bekor qilish (Revert) Safe Public Undo
Vaziyat:
Commit GitHub-ga yuklab bo'lingan
Teskari buyruq:
git revert <commit-hash>
Eski tarixni buzmagan holda, o'sha commitni aksini qiluvchi YANGI commit yaratadi.
5

Branch (Tarmoqlanish) va Merge

Yangi funksiyalarni asosiy kodingizga (main) zarar yetkazmagan holda alohida tarmoqda (branch) yozish tavsiya etiladi.

BRANCH YARATISH & O'TISH 
git branch feature-login
git checkout feature-login
# Yoki ikkalasi birda:
git checkout -b feature-login
BRANCH O'CHIRISH (TESKARI) 
git checkout main
git branch -d feature-login
# Majburiy o'chirish:
git branch -D feature-login
MERGE QILISH (BESH-KATTALASHTIRISH) 
git checkout main
git merge feature-login

Agar merge paytida bir xil qatorda ixtilof bo'lsa (Merge Conflict), faylni ochib <<<<<<< va >>>>>>> orasidagi kerakli kodni qoldirasiz, keyin git add . va git commit qilasiz.

6

GitHub bilan Ishlash (Remote Repository)

Lokal kompyuterdagi loyihani bulutga (GitHub) yuklash yoki tayyor loyihani kompyuterga ko'chirib olish (Clone). 

# 1. Masofaviy omborni bog'lash
git remote add origin https://github.com/foydalanuvchi/loyiha.git

# 2. Kodni GitHub-ga yuklash (Push)
git push -u origin main

# 3. GitHub-dagi yangi o'zgarishlarni kompyuterga tortib olish (Pull)
git pull origin main

# 4. Tayyor loyihani internetdan ko'chirib olish
git clone https://github.com/foydalanuvchi/loyiha.git
REMOTE BOG'LANISHNI UZISH (TESKARI) 
git remote remove origin
7

Pull Request (PR) va Code Review

Jamoada ishlaganda hech qachon to'g'ridan-to me main branchiga push qilinmaydi. Buning uchun Pull Request ishlatiladi.

  1. Yangi branch ochasiz va o'zgarishlarni yuklaysiz: git push origin feature-login
  2. GitHub saytiga kirib, "Compare & pull request" tugmasini bosasiz.
  3. Jamoa a'zolari kodingizni ko'rib chiqadi (Code Review).
  4. Hamma narsa joyida bo'lsa, "Merge pull request" bosiladi.
8

Loyihani Internetga Deploy Qilish

GitHub-dagi kodingizni avtomatik ravishda bepul servislarga joylashtirish (Deploy) bosqichlari:

GitHub Pages

Statik HTML/CSS/JS loyihalar uchun ideal. Repository Settings → Pages bo'limidan main branch tanlanadi.

Vercel

Vercel.com ga GitHub orqali kirib, repository-ni tanlaysiz. Har safar git push qilganingizda avto-deploy bo'ladi.

Netlify / Render

Frontend va Backend loyihalar uchun qulay avtomatik CI/CD deploy platformasi.
